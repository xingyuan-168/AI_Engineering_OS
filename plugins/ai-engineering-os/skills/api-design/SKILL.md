# API design

Define resources or operations, authentication and authorization boundaries, request and response schemas, validation, pagination, idempotency, concurrency, errors, rate limits, observability, and versioning. Make database or transport details visible only when they are part of the public contract.

Trace endpoints and events to acceptance criteria. For changes, describe compatibility, deprecation, migration, retry, and rollback behavior. Validate examples against the schema and document security-relevant failure paths. Do not claim an external integration contract without a cited authoritative source or fixture.
