# Interaction design

Translate approved journeys into complete flows covering entry, success, empty, loading, validation, permission, error, retry, cancellation, and recovery states. Specify keyboard and assistive-technology behavior, focus movement, feedback timing, destructive-action confirmation, and responsive interaction changes where relevant.

Tie every flow to its requirement and acceptance criterion. Mark missing policy, content, or data decisions as blockers. Produce implementation-ready behavior and a handoff that lets UI, frontend, and QA identify each state without relying on chat history.
