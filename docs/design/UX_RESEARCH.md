# UX Research 设计依据

版本：V2.0-derived-ux
状态：可执行设计基线
适用：未来控制台、桌面端或 Web/App；当前 CLI MVP 使用其信息架构结论。

## 1. 用户画像

| 用户 | 目标 | 核心困难 | 关键需求 |
| --- | --- | --- | --- |
| 个人开发者 | 从业务目标快速交付 | 上下文丢失、流程管理负担大 | 一键启动、状态可见、失败可恢复 |
| 技术负责人 | 控制架构和依赖风险 | 不知道 Agent 为什么这样决定 | 决策证据、影响检查、可审计 Review |
| QA/Security | 证明质量和安全 | 测试、依赖和命令证据分散 | 统一证据、阻塞原因、风险分级 |
| Reviewer | 快速判断是否可合并/发布 | 变更范围和未解决问题不清晰 | 变更摘要、测试、权限和回滚信息 |

## 2. 主要场景

- 新项目初始化和 G0 范围确认。
- 查看 Workflow 当前阶段、下一动作和阻塞原因。
- 审批 G0-G4 并查看证据。
- 查看 Agent 任务、Worktree、变更文件和交接包。
- 处理失败、重试、暂停和恢复。
- 查看发布候选物、测试、安全、Review 和审计证据。

## 3. 用户痛点

- 不知道项目处于哪个阶段。
- 不知道为什么流程被阻塞。
- 不知道 Agent 修改了什么、在哪个分支修改。
- 不知道架构决策、测试结果和安全报告在哪里。
- 不知道当前状态是否可以安全发布。

## 4. 参考对象

| 参考 | 可借鉴机制 | 不直接复制 |
| --- | --- | --- |
| Codex/IDE | 执行上下文、代码导航、工具反馈 | 不替代项目状态和门禁 |
| GitHub/GitLab | Commit、Review、CI 证据 | 不替代本地 Workflow |
| Linear/Jira | 任务、状态、负责人 | 不把文档事实拆散到任务系统 |
| LangGraph/Agent 控制台 | 流程图、运行状态、节点日志 | 不引入第二套状态真相 |

## 5. 设计假设

- 用户首先关心当前动作、阻塞原因和是否需要审批。
- 证据必须能从状态、任务和发布页面直接跳转。
- 高风险操作必须展示影响、路径、命令和回滚方式。
- 空态、错误态、阻塞态和恢复态与成功态同等重要。
- 用户不应被迫阅读完整日志才能判断下一步，但必须可以展开原始证据。

## 7. 研究验证

进入前端实现前，至少用 ERP 采购模块试点验证：用户能否在 30 秒内找到当前阶段和下一动作；能否在 2 分钟内找到阻塞原因和证据；能否识别高风险操作；能否从失败状态恢复；能否判断发布是否满足 G4。

## 8. 完成定义

UX Research 只有在画像、场景、痛点、参考对象、设计假设、映射关系和验证标准均明确时才算完成。
