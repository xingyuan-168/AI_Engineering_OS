# UI 规范

状态：可执行设计基线

## 信息层级

1. 项目上下文：项目名、Workflow、状态、风险。
2. 当前动作：下一步、待审批、阻塞原因。
3. 证据：文档、提交、日志、测试和安全结果。
4. 辅助信息：时间、Agent、分支和历史事件。

## 状态表现

| 状态 | 颜色语义 | 必须显示 |
| --- | --- | --- |
| `ready` | 蓝色 | 可执行动作和前置条件 |
| `running` | 青色 | 当前步骤、开始时间和取消入口 |
| `blocked` | 琥珀色 | 阻塞原因、责任人和解除条件 |
| `failed` | 红色 | 错误类别、日志、恢复点和重试 |
| `approved` | 绿色 | 审批人、时间和证据 |
| `completed` | 深绿色 | 产物、提交和下一阶段 |

颜色不能是唯一状态信号；必须同时显示文字、图标或结构变化。

## 交互规则

- `批准`、`退回`、`暂停`、`恢复`、`重试` 和 `合并` 都必须二次确认并记录理由（低风险恢复可配置为一次确认）。
- 删除、迁移、生产发布和凭据访问使用危险操作样式，默认不可自动执行。
- 长日志默认折叠，但必须可展开、复制和定位到具体事件。
- 所有表单字段显示校验错误、修复建议和提交后结果。
- 键盘可完成主要导航、列表筛选、详情展开和审批操作。

## 响应式与可访问性

- 桌面端采用左右分栏；移动端改为上下堆叠，不隐藏审批和阻塞信息。
- 正文最小 14px，按钮触控区域最小 40x40px。
- 文本与背景满足 WCAG AA 对比度；焦点状态始终可见。
- 表格提供表头、行标题和屏幕阅读器可理解的状态文本。

## 验收

设计交付必须包含成功、空态、加载、阻塞、失败、审批、恢复和完成状态截图或可交互原型，并能映射到 `USER_FLOW.md` 的每条分支。
