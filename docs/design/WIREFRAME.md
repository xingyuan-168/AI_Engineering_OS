## 页面 1：项目总览

```text
+--------------------------------------------------------------+
| 项目名称 / 当前 Workflow / 风险级别       [继续] [暂停]      |
+----------------------+---------------------------------------+
| 阶段导航             | 当前阶段摘要                         |
| G0 范围              | 状态、负责人、阻塞原因、下一动作       |
| G1 需求              | 产物列表、最近事件、待审批             |
| G2 设计              |                                       |
| G3 质量              |                                       |
| G4 发布              |                                       |
+----------------------+---------------------------------------+
```

## 页面 3：门禁审批

```text
+--------------------------------------------------------------+
| G2 架构确认                       风险：中                     |
| 需要确认：架构、技术栈、API、数据库、外部依赖                 |
| 证据：文档链接 / ADR / 测试 / License                         |
| [批准] [退回并说明原因] [暂不处理]                            |
+--------------------------------------------------------------+
```

## 页面 4：执行与错误

- 命令、工作目录、风险级别和预计影响必须在执行前可见。
- 失败显示错误类别、日志链接、恢复点、重试次数和人工操作建议。
- 不允许只显示“执行失败”而隐藏实际命令、路径或退出码。

## 布局约束

- 页面使用单一主导航和明确的当前项目上下文。
- 关键操作固定在详情区域底部，避免随列表滚动丢失。
- 表格列允许折行；状态和风险使用文字 + 颜色，不只依赖颜色。
- 所有空态提供下一步动作；所有阻塞态提供原因和解除条件。
