# ADR-0008：治理证据、授权和环境操作可靠性

## 背景

审查发现旧成功检查可能掩盖新失败，环境操作借用其他操作类型，网络审批和公开对账入口未充分验证事实。声明式规则必须由执行、证据和状态约束共同实现，不能只增加规则文本。

## 决策

1. Gate 先选择最新尝试，再判断结果。G3 检查与 Review 绑定精确目标 Commit；继承文档必须复验目标 Commit 的内容 hash。报告在 preflight/审批时重新读取。失败、拒绝和撤销不能由旧成功覆盖。
2. SQLite 追加 0008，登记正式环境操作类型、授权、执行尝试、资源归属和证据上下文；0001 至 0007 不改写。旧记录保留审计，无法证明的状态必须重新验证。
3. 网络批准必须是持久化、有范围和有效期的独立授权。OS principal、Runtime actor 和任务角色分别记录；本地人工确认不作为普通 Agent MCP 授权工具。本地模型不防御已控制宿主账户的攻击者。
4. 外部对账结论只由受信执行器观察事实后产生。续租、执行代次、任务取消和期望版本共同约束副作用，不能以调用方声明成功结束操作。
5. OCI 验证消费干净 Commit、规范 Compose 和不可变镜像快照；隔离操作资源，使用随机持久化数据和实际容器替换证明重建，不访问真实业务 Volume。
6. 核心约束、Profile 能力和项目检查分层；共享注册表连接执行、证据与 Gate。保留前端 HTML 原型和独立确认，不允许以精简为由降低要求。
7. 本机日常 runtime 安装已验证 wheel，不使用 editable，也不回退项目 .venv；插件缓存版本与正式包基础版本分别管理。

## 验证与恢复

优先加入假通过、并发、崩溃、取消和策略漂移的负向回归。迁移前使用 SQLite backup API 并校验备份，失败恢复先验证临时数据库再替换；已有新写入时禁止盲目恢复旧备份。真实 OCI、独立 Review、G3/G4 未完成时不得声明正式发布完成。

## 替代方案与后果

拒绝继续借用 0007 的 operation kind、仅补 Hook 正则或仅增加文档要求；这些做法不能修复恢复分派和证据可信性。升级将使证据不足的旧 Workflow 进入 revalidation，但不会删除原始事件、审批、Git 历史或持久数据。
