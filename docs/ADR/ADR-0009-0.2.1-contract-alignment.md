# ADR-0009：0.2.1 契约对齐与证据绑定语义澄清

- 状态：Accepted（用户批准本轮评审修复实施方案；不替代独立 Gate/发布审批）
- 日期：2026-09-05
- 决策版本：0.2.1 / API 1.2 / SQLite 0008

## 背景

0.2.1-oci-first 合入后遗留三类缺口：版本事实散落多处（CLI 迁移目标硬编码 `0007`、插件包名硬编码 `0.2.0`、测试断言字面量），OCI-first 环境治理只定义了 Gate 要求而缺少证据生产者，且 G3 检查/Review 的"精确目标 Commit"实现为字符串相等，与 Handoff 集成合并后 `last_commit_sha` 指向合并提交的既有流程矛盾，导致 E2E 受管流程无法到达 G4。

## 决策

1. `RUNTIME_VERSIONS` 是唯一版本事实源。CLI `database migrate` 默认目标、状态输出断言、发布产物命名（wheel、sdist、`ai-engineering-os-plugin-{RUNTIME_VERSIONS.plugin}.zip`）、插件 manifest 版本校验一律从 `RUNTIME_VERSIONS` 派生；测试断言同样引用该常量，不再复制字面量。
2. OCI-first 环境证据闭环补全生产者：G2 要求环境契约文档/制品与 `environment-contract` 检查；G3 要求环境准备与重建证据制品及五项环境检查；G4 的 `environment-reconciliation` 记录取该 Run 最新成功的 `environment_*` Host Operation（操作标识、类型、请求 hash、状态版本与结果载荷的联合 hash），由证据束组装时生成，不由调用方声明。
3. G3 检查与 Review 绑定语义澄清为：证据的 `source_commit` 必须是 Gate 目标 Commit 或其祖先（每名取最新尝试），且报告内容 hash 必须在目标 Commit 上复验一致；`html-prototype-validator` 与 `ux-prototype` 仍要求与目标 Commit 精确相等。该澄清落实 ADR-0008 §1 的意图（最新尝试 + 内容复验，旧成功不得覆盖新失败），同时兼容集成合并提交作为目标 Commit 的正常流程。
4. 设计阶段任务的可写路径纳入环境契约文件（`docs/ENVIRONMENT.md`、`.codex-os/environment.yaml`、`.dockerignore`、`compose.yaml`、`docker/`），使 G2 环境设计在同一受管任务内完成并被允许路径约束。
5. SQLite 迁移表名匹配使用词边界比较，禁止前缀误匹配（`host_operations_next` 不再误认 `host_operations`）。

## 替代方案与后果

拒绝继续维护多处版本字面量（随每次版本升级产生连带失败），拒绝为环境证据引入调用方可伪造的登记接口，也拒绝将 G3 相等条件整体删除（那会重新允许原型验证漂移）。放宽为"祖先 + 内容复验"后，真正的陈旧证据仍被每名最新尝试与内容 hash 校验拒绝；若未来要求检查必须在合并提交上重跑，应以显式门禁规则收紧，而不是隐式丢弃全部祖先证据。
