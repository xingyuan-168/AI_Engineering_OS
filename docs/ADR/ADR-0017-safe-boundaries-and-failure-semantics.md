# ADR-0017：目标路径、数据保全与失败语义

- 状态：Accepted（用户批准源码审计与修改方案，2026-09-24 继续实施）
- 日期：2026-09-24
- 适用：保持 ADR-0016 的三 Gate、8 MCP 工具、8 Skill、配置 1.2；澄清其安全边界，不增加 Agent Runtime。

## 上下文

宿主曾以 `CreateProcess ... blocked by policy` 拒绝临时构建目录删除，当时 approval_policy=never；未提供具体规则，不能归因为 AIOS 或 Auto-review。独立源码复现发现 AIOS 按 cwd 而非删除目标放行、branch -d/-D 混淆、Hook 不支持的 ask/失败后继续，以及批准撤销、数据库重建、Memory 候选丢失、Finish 已提交代码漏检问题。

## 选项与决定

1. 不增加清理凭证/任务归属状态机。由 Codex 原生上下文确认用户授权与任务归属；AIOS 只检查可观测目标、保护路径、Git 跟踪与链接边界。变量/复杂目标无法证明时明确拒绝。不得通过 cwd/Shell/语言切换绕过宿主拒绝。
2. Hook 正常路径只调用一套授权内核；Runtime 失败时敏感操作明确 deny，读操作报告未知。不输出 ask，也不从脏文件反推用户所有权。外层/Runtime/网络预算分别为 15/10/5 秒。只读 explain 不代表宿主审批。
3. 文档事实优先：前端批准和拒绝均改写 Git 管理的批准块，绑定 scope 与设计内容摘要；旧批准重新确认。SQLite 只是派生记录。
4. 拒绝未知数据库的自动重建。只对已审计历史结构显式迁移，先做包含 WAL 的一致性备份，再事务替换；忙库、活动 Worktree、备份失败保持原样。Memory 候选只在成功或完全一致的已合入记录确认后清理，写锁防止丢记录。
5. Finish 基线由任务开始时的原生上下文保存；显式传递给 CLI/MCP，覆盖已提交、暂存、工作区和未跟踪变更。缺失即阻塞，不静默采用当前 HEAD。保持 Gate 无隐藏任务状态。

## 后果与必要性

本 ADR 是安全行为改变的单一决策记录，避免重新解释历史 ADR；API/数据库/工作树/Memory 文档只更新相关契约。新增的是既有命令的参数，不是新调度/审批系统。回归测试使用模拟删除载荷和隔离夹具，不以业务资产做破坏性验证。部署、插件信任、运行库迁移和宿主设置仍须独立授权，测试通过不代表当前任务已加载新版 Hook。

官方契约依据：[Hook 协议](https://learn.chatgpt.com/docs/hooks)、[审批边界](https://learn.chatgpt.com/docs/sandboxing/auto-review)。更细的历史宿主拒绝原因缺乏证据，保留未知。
