# Codex AI Engineering OS 产品需求

版本：V2.0-derived
状态：可执行文档基线

## 产品目标

让用户以业务目标驱动软件研发，由系统完成需求、设计、执行、质量、发布和经验沉淀，同时保留人可检查的依据和审批点。

## 用户

- 个人开发者：希望减少重复分析和工程管理工作。
- 技术负责人：需要架构、依赖、风险和决策可追溯。
- 质量/安全角色：需要测试、Review、License 和命令执行证据。

## MVP 功能

1. 目标输入、项目初始化和复杂度判断。
2. 标准文档生成、读取、完整性和变更影响检查。
3. Workflow 选择、状态管理、暂停、恢复和重试。
4. Skill/Agent 调度、Worktree 隔离和产物汇总。
5. 受控命令执行、测试、Review、安全扫描和发布候选物。
6. 开源项目调研、License 审核和长期经验沉淀。

## 验收标准

- 输入一个业务目标可生成标准项目文档和初始 Workflow。
- 缺少范围、架构或安全产物时不能进入对应门禁。
- 关键变更有人工确认，所有执行有日志。
- 中断的 Workflow 可恢复，失败方案可检索。
- 发布候选物能关联需求、提交、测试、Review 和 CHANGELOG。

## 非功能要求

- 可追踪：目标、任务、产物、审批、提交和发布物可通过 ID 关联。
- 可恢复：Workflow 中断后从最后检查点恢复，重复执行具备幂等保护。
- 可控：命令、文件、依赖和发布均受策略约束。
- 可迁移：事实文档使用 Markdown + Git，不绑定某个 Agent 框架。
- 可验证：每个门禁有明确输入、输出和失败状态。

## 产品完成定义

需求文档只有在功能、非功能、用户故事、边界和验收标准全部存在，且每项验收标准都能映射到测试场景时才算完成。
