# 业务规则与治理规则

状态：可执行治理基线

## 事实来源规则

1. `docs/` 是项目事实来源；代码与文档冲突时先暂停实现。
2. 新项目必须先完成目标、范围、需求和验收标准，再进入设计。
3. 需求变更先做影响检查，再修改代码或配置。

## 设计与依赖规则

4. 任何功能修改必须检查 API、数据库、架构、ADR 和 CHANGELOG 影响。
5. 开源依赖未完成版本、License 和安全核验时不得正式引入。
6. 涉及 UI 的项目必须先完成 User Flow、原型、UI 规范、组件和设计 Token。

## 协作与执行规则

7. 复杂项目启用 Multi-Agent；每个 Agent 独立 Branch/Worktree。
8. 所有命令和文件写入经过 Execution Manager 的路径、风险、超时和审批策略。
9. 破坏性命令、敏感数据操作和生产发布必须人工确认。

## 版本与记忆规则

10. 禁止 `v1/v2/new/final/backup/copy` 复制目录作为版本管理手段。
11. 失败结果必须记录原因、影响、恢复方式和是否复用。
12. 阶段只有在代码、文档、测试、Review、安全和变更记录齐全后才算完成。

## 规则例外

例外必须记录适用范围、原因、风险、替代控制、批准人和失效日期；例外不能通过删除日志或绕过门禁实现。
