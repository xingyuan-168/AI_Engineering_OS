# AI Engineering OS Codex 历史执行入口文档

> **历史资料，不是现行执行指令。** 本文保留早期“构建 AI Engineering OS”阶段的目录设想和推进记录，仅用于审计追溯。当前仓库行为以根目录 `AGENTS.md`、`docs/PROJECT_MASTER.md`、`docs/SCOPE.md` 和 `docs/README.md` 的读取顺序与已接受 ADR 为准；本文中的 Plan Mode、旧目录、DeepSeek Harness 或阶段命令不得覆盖这些事实源。

## 文档目的

本文档曾作为 AI Engineering OS 项目的建设入口，现已归档。

用途：

指导 Codex / DeepSeek Harness Agent
在读取项目规范后，按照正确顺序推进开发。

本文件不是功能设计文档，而是：

-   项目启动流程

-   验收标准
-   执行约束

-   系统边界
-   模块职责
-   开发规则

## Step 2：建立项目上下文

生成：

    PROJECT_CONTEXT.md

内容：

-   当前项目目标
-   核心模块
-   技术栈
-   已有能力
-   待开发能力
-   风险点

该文件作为后续开发上下文。

# 三、进入Plan模式

Codex必须进入Plan Mode。

生成：

    IMPLEMENTATION_PLAN.md

计划必须包含：

## 1. 当前状态分析

包括：

-   项目结构
-   已实现功能
-   缺失功能

## 2. 架构影响分析

分析：

-   哪些模块影响
-   哪些文档需要更新
-   是否影响API
-   是否影响数据库

## 3. 开发阶段划分

必须按照阶段执行。
